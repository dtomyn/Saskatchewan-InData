# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Living Skies Atlas: a static, no-backend Vite + TypeScript web app that maps Saskatchewan's safety, justice and land in open data on a 3D map (MapLibre basemap + deck.gl layers + d3 charts). It is the Saskatchewan sibling of Island Atlas (`C:\HouseShopping-VancouverIsland`) and keeps its framework, look and conventions; `MAP-ATLAS-BLUEPRINT.md` describes them, with this atlas's brief filled in as Part 1.

## Commands

```bash
npm run dev               # http://localhost:5173 (.claude/launch.json: "living-skies")
npm run build             # tsc --noEmit + vite build: the only automated check (no tests, no linter)
npm run data [stage…]     # rebuild public/data/*.json from the original sources
npm run data now          # the eight live stages only (public/data/now/, not committed)
npm run data now water history  # …and roll them into the daily record (public/data/history/, the data-history branch; history counts only freshly refreshed fires, alerts and water)
.venv/Scripts/python.exe video/render.py --storyboard   # the explainer film's storyboard (README: The explainer film)
.venv/Scripts/python.exe video/render.py --preview --only finder   # one scene at 960x540, no sound
.venv/Scripts/python.exe video/render.py --film sky --storyboard   # the narrative film, Come for the sky (video/storyboard_sky.py)
```

`.claude/launch.json` also has `living-skies-alt` (dev on 5174) and `living-skies-built` (`npm run preview` on 4175: the production build, so the CSP applies). `npm run data` with no stage runs everything except `history` and `history-backfill`, which run only when named. A cold run of `justice`, `hospitals`, `camping`, `schools`, `newcomer`, `doctors` or `childcare` takes minutes: they call the public OSRM demo router once a second. Pushing to `main` deploys (`deploy.yml`), so work on a branch and open a pull request.

The explainer film (`video/render.py`, scenes in `video/storyboard.py`) drives the app by its Layer menu names and DOM selectors (`#layers-btn`, `.layer-row`, `#panel .work-sel`, `.weight input[data-id]`, `[data-preset]`, `.small-on`, `.sc-pick`, `#scenario-banner .sb-clear`, `.now-block`, `.proj-table`, `[data-show]`, `.tr-ct-chips [data-ct]`, `.src-round canvas`, `.src-go`): when a feature it films changes, update the storyboard and re-render it. The narrative film *Come for the sky* (`video/storyboard_sky.py`, `--film sky`) reuses the how-to's helpers and also drives `#panel [data-m]` (Light & dark's chips), `.reach-go` and `[data-lim]` (Weekend Reach), `#terrain-btn`, `[data-twin]` and `.twin-town` (Climate twin), `atlas.replaySeason()` and `#finder-btn`; its `prepare` stops the film when the data no longer says what a line says. Both load the live readings and the daily record: run `npm run data now`, put the `data-history` branch in `public/data/history/` and `npm run build` before filming (the film clock reads `dist/data/now`; without a recorded fire day the how-to stops, without a season to replay the sky film stops). `--start` writes `…-from-<scene>` files only; a film other than the how-to keeps its narration in `video/out/vo/<NAME>/`.

No neighbourhood crime: Regina Police's area workbooks and 90-day FeatureServer carry no licence, Saskatoon publishes city-wide only. `places` writes `municipalities.json`, which `jobs`, `needs`, `justice`, `hospitals`, `camping`, `schools`, `newcomer`, `doctors`, `childcare`, `industry`, `water`, `radon` and `commute` read; `schools`, `internet`, `community`, `doctors`, `childcare`, `industry` and `radon` also read `needs.json` (town limits); `doctors` reuses `hospitals`' ODHF download and `needs`' Overpass answer (`NEEDS_KINDS`, `needsOSM`); `community` reuses `censusProfile` and caches the characteristic codelist in `.cache/census/CL_CHARACTERISTIC.xml`. `internet` streams ~400 MB of ISED zips once and caches Saskatchewan's pseudo-households in `.cache/internet/sk-phh-speeds.tsv`. `water` reads the province's two advisory PDFs with a small text extractor (`pdfText`, `advisoryRows`) and places them with the CGNDB gazetteer (cached per feature type in `.cache/cgndb/sk-<TYPE>-<skip>.json`); its downloads cache per day in `.cache/water/`. `industry` pages ~120,000 well rows from the GeoHub (60 requests, cached in `.cache/arcgis/sk-wells-*`) and caches the latest NPRI single-year CSV (~40 MB) in `.cache/npri/`. `smoke` streams NAPS's yearly all-Canada PM2.5 files and caches only their Saskatchewan rows in `.cache/naps/` (a year with none yet is not cached, so it is fetched again next run). `drought` reads `municipalities.json` and the province outline and asks AAFC's drought image service for each month's raw categories (`exportImage`, `format=bsq`: the bytes are followed by a 1-bit mask, so only the first w×h are read) on a 10 km Web Mercator grid, one request a month cached in `.cache/drought/`; the catalogue is cached per day. `fires` also reads the National Burned Area Composite from CWFIS's GeoServer (WFS 1.0.0, `public:nbac`, EPSG:4326, one Saskatchewan year per request, ~20 MB for a big year, cached in `.cache/nbac/`; the year list is cached per day) and links each outline to the same-year start points inside it. `crops` reads `municipalities.json` and the province outline and asks AAFC's `annual_crop_inventory/<year>` image services for raw categories (`exportImage`, `format=bsq`, U8) sampled at 500 m in three strips a year (cached in `.cache/crops/`, ~6 MB a year), folding each 6 × 6 block into a 3 km Web Mercator cell's most common class. `power` reads `municipalities.json` and `needs.json` (town limits) and two Overpass answers (`sk-power-lines.json`, `sk-power-sites.json`). `hail` reads `municipalities.json` (to place a research-database storm whose point is off the map) and joins the Northern Hail Project's per-bend swath pieces back into one track. `radon` reads Health Canada's survey CSV and StatCan's 2007 health region shapefile (Statistics Canada Lambert, parsed and unprojected in the stage; no shapefile library) from `.cache/radon/`. `projections` reads ECCC's CanDCS-U6 30-year coverage on GeoMet (`climate:candcsu6:projected:annual:P30Y-Avg/coverage`, `subset=scenario(…),percentile(…),P30Y-Avg(…)`; 18 province grids cached in `.cache/projections/`) and samples each place's cell. `voting` reads Elections Canada's poll-by-poll results zips (2011–2025, cached as `.cache/voting/results-<year>.zip`; UTF-8 with a BOM from 2015, Latin-1 for 2011, so each file is decoded by its bytes), the 2015, 2019 and 2021 national polling division shapefiles (80–95 MB each, `.cache/voting/pd-<year>.zip`, Statistics Canada Lambert, read with `scripts/lib/shp.mjs`: the .dbf first, then only Saskatchewan's shapes through the .shx), the 2025 polls and ridings from the `FED_Elect2025_en` MapServer as KMZ (its JSON and GeoJSON answers carry no geometry; one request a riding, `.cache/voting/pd-2025-<fed>.kmz`), the 2013-order riding shapefile and the Library of Parliament's `hfer_e.csv`; it reads `municipalities.json`, `needs.json` and `subdivisions.json` (town limits) and writes `voting.json` (ridings, history, places) and `voting-polls.json` (each election's polls as delta-encoded integer rings, loaded by the app on first use). `twins` downloads nothing: it reads `normals.json` and `projections.json` and matches each place's projected climate to a station's normals today (Data notes: Climate twins). `floods` reads the Water Security Agency's `1_500yr_Flood` and `Flood_Hazard_All` FeatureServers (cached in `.cache/arcgis/wsa-flood-*`). `buildings` reuses those cached answers unsimplified, reads `subdivisions.json` (town limits), Microsoft's Canadian Building Footprints (`Saskatchewan.zip`, 22 MB, cached in `.cache/buildings/`, one feature a line, streamed with `zipLines`) and an Overpass answer (`sk-building-heights.json`), keeps the footprints around each flood-mapped community and Regina and Saskatoon, flags each against the extents, and writes `public/data/tiles/buildings.pmtiles` (committed, ~14 MB; zoom 12–15, layers `buildings` {`f`, `h`} and `flood` {`k`}; `scripts/lib/pmtiles.mjs` is the writer, tiles cut with `geojson-vt` and `vt-pbf`) and `buildings.json` (per-area counts); it throws over 40 MB. `hospitals` and `justice` (courts) keep each place's three fastest sites by road (`driveTimes` `keep`), which the closure scenarios fall back on. `transit` reads `needs.json` (town limits) and caches OurAirports' CSV and the four city GTFS zips in `.cache/transit/`; it keeps only each route's longest shape. `tax` reads the Ministry of Government Relations' latest Mill Rate Survey workbook (Publications Centre product 72573, cached in `.cache/tax/`; when the Publications Centre answers 502 it uses the Internet Archive's copy of the same URLs) with a small xlsx reader (columns found by header text), and reads `municipalities.json` and `housing.json` (median home value for the indicative tax). `light` computes day length and geomagnetic latitude itself and reads `camping.json` (park outlines, campgrounds) and `province.json`; it caches IAGA's IGRF-14 coefficient file and RASC's dark-sky table in `.cache/light/`. Raw downloads cache in `.cache/`; a failing stage keeps its old JSON and records the error in `public/data/manifest.json`. `public/data/` is committed, except `public/data/now/`.

The live stages (`now-*`; `npm run data now` runs all eight) cache nothing and write `public/data/now/<name>.json` with `asOf`, `fetched`, `source`, `sourceUrl` and the licence, and their own `now/manifest.json` (merged by `loadAll`), so they never change a committed file. `now-rivers` reads `rivers.json` (gauges, `median`) and pages `hydrometric-realtime` for the last 24 h; `now-fires` reads CWFIS's GeoServer WFS 1.0.0 (2.0.0 with EPSG:4326 swaps the bbox axes) for `hotspots_last24hrs` and `m3_polygons_current` (season to date; kept while heat was seen within 7 days); `now-air`, `now-alerts` and `now-outlooks` read `municipalities.json`; `now-outlooks` reads the thunderstorm outlook (OGC API), CWFIS's `fdr_current_shp` (WFS 1.0.0, the day from its WMS title) and RAQDPS's `Sfc_PM2.5-WildireSmokePlume-DMax` (sic) by WMS GetFeatureInfo per place (kg/m³ × 1e9 = µg/m³); a part that fails is left out. `now-aurora` reads NOAA SWPC's OVATION grid (`ovation_aurora_latest.json`, the whole globe at 1°, longitudes 0–359) and keeps a window over western Canada (125–85° W, 44–75° N), plus the latest planetary Kp and the predicted Kp windows of the next 36 h (`kpNext`; each left out when it fails). `now-wind` and `now-plume` read MSC GeoMet's WCS (`scripts/lib/geomet.mjs`: `layerTimes` from a layer's WMS capabilities, `airGrid` for one valid time as an uncompressed float GeoTIFF read by `scripts/lib/tiff.mjs`) on the air grid (`AIR_GRID`: 0.25° nodes from 112° W, 47.5° N, 51 × 57, rows south to north): the RDPS's `RDPS_10km_WindSpeed_10m` and `RDPS_10km_WindDir_10m` for the hour nearest now (GeoMet has no surface u and v, so they are worked out; ints in steps of 0.25 m/s), and `RAQDPS.Sfc_PM2.5-WildfireSmokePlume` every third hour from now to the end of the run (kg/m³ × 1e9; a byte a cell, `round(10·√µg/m³)`, zero runs packed as `[0, n]`, base64; a frame that fails is left out). `.github/workflows/live.yml` runs `npm run data now water`, builds and deploys hourly, and `deploy.yml` runs the same stages on a push (it never cancels a live run); both first download the `now/` files the site serves, so a failed feed keeps its last file. Actions are pinned by commit SHA. `driveTimes` is all or nothing: if OSRM fails part-way, every place gets straight-line trips, and a stage that routes several sets makes them all straight-line, so minutes and kilometres never mix. Cache writes and published JSON are written to `.part` and renamed; `cached` refuses a name outside `.cache/`.

## Rules for this repo

- All data comes from `npm run data` stages, never hand-edited JSON. The only hand-typed data is the place-name list in `scripts/places.mjs`, the curated events in `src/curated-events.ts` (`CURATED_EVENTS`, well-documented facts only, each with a source link) and the province's settlement-services list `SK_SETTLEMENT` in the `newcomer` stage (`scripts/stages/newcomer.mjs`) (typed from saskatchewan.ca, with its source link and the date read in `SK_SETTLEMENT_ASOF`; re-check it when rebuilding).
- Anything from outside the code (OSM names, data strings) goes through `esc()` / `safeUrl()` in `src/html.ts` before `innerHTML`. The production build ships a CSP (`vite.config.ts`).
- Say when a value is inferred or borrowed: the in-town police rule (`nearestJustice` in `src/justice.ts`), borrowed climate stations, rural RCMP detachments standing in for a town.
- When you change a behaviour the blueprint describes (layer menu rules, event panels), update `MAP-ATLAS-BLUEPRINT.md` and the README with it, and the intent in `intents/` that points at it (one file per thing people come to do, each with a `?film` check; a feature should serve at least one).
- `ROADMAP.md` lists what is built and what is next (✅ built, *(verify)* = source not yet confirmed open).

## Architecture

Same shape as Island Atlas:

- **`src/main.ts`** owns state (`visible`, `focused` — `'province'` means none active — `timeLayer`, `mode: layer | town | finder | event`), the frame loop, the layer menu (`setLayerOn`, `focus`, `clearMap`), click routing and the timeline. `?film` exposes `window.atlas`.
- **`src/layer-kit.ts`**: the `AtlasLayer` contract (`Ctx`, `AtlasEvent`, `TimedEvent`, `RecentSpan`) and the helpers every layer module shares (`rgb`, `kicker`, `heroStats`, `deferChart`, `townColumns`, `dashExt`…). Layer modules import from it, never from `layers.ts`, so there is no import cycle.
- **`src/layers.ts`**: the registry only: `buildLayers()` (menu order) and the base `province` layer. **`src/curated-events.ts`**: `CURATED_EVENTS`.
- **`src/fires.ts`** (Wildfires), **`src/rivers.ts`** (River floods; its city close-ups are **`src/buildings.ts`**: the PMTiles source, MapLibre's `fill-extrusion` buildings and the water sheet, `syncBuildings` tinting them while River floods is on, and the terrain button), **`src/climate.ts`** (Climate), **`src/normals.ts`** (Climate normals), **`src/population.ts`** (Population), **`src/housing.ts`** (Home costs, with property tax), **`src/jobs.ts`** (Jobs & income), **`src/needs.ts`** (Daily needs), **`src/radon.ts`** (Radon), **`src/crime.ts`** (Crime severity), **`src/hospitals.ts`** (Hospital access), **`src/justice.ts`** (Courts & police), **`src/treaties.ts`** (Treaties & reserves), **`src/camping.ts`** (Camping & rec), **`src/tornado.ts`** (Tornadoes), **`src/hail.ts`** (Hail), **`src/drought.ts`** (Drought), **`src/crops.ts`** (What grows here), **`src/schools.ts`** (Schools & learning), **`src/internet.ts`** (Internet & mobile), **`src/community.ts`** (Who lives here), **`src/newcomer.ts`** (Newcomer services), **`src/doctors.ts`** (Doctors & clinics), **`src/childcare.ts`** (Childcare), **`src/smoke.ts`** (Smoke & air), **`src/industry.ts`** (Hidden neighbours, with the power grid), **`src/water.ts`** (Drinking water), **`src/light.ts`** (Light & dark), **`src/transit.ts`** (Getting around), **`src/commute.ts`** (Workday Reach; its workplace setting lives in `metrics.ts` and is shared with the Finder), **`src/voting.ts`** (Voting: the poll map from `loadVotingPolls`, the dots placed in the browser, the seat chart, `votingRows` in the Town Report and small-community report; `AtlasLayer.opensAt` opens its timeline on the latest election): one layer each.
- **`src/scenario.ts`**: what-if closures (hospitals, courthouses): closed sites, `scenarioTrip`, `affectedTowns`, the panel box; `main.ts` draws the banner on `atlas:scenario`. Never read by `metrics.ts`. **`src/projections.ts`**: climate projection helpers (`projAt`, `provinceBand`, the Town Report row); `AtlasLayer.projection` hatches the timeline past the record, and `bandChart` (charts.ts) draws record bars then bands.
- **`src/twins.ts`**: climate twins: the Climate layer's Climate twin chip (`twinPanel`, its state, period slider and scenario chips), the arcs (`twinLayers`; drawn in place of the layer's columns while the chip is on), `twinClick` (a click on a place, or on a town pin while Climate is focused, picks it: `main.ts` offers the focused layer's `click` a town-pin click before opening the report), the Town Report row (`twinRow`) and `openTwin(key)`. It only draws what the `twins` stage matched.
- **`src/now.ts`**: the live-reading rules (ages, 3 h stale, 24 h not drawn, `NOW_T`, `isNow`), the Right now block, weather alerts (`alertsInEffect` by layer, dashed outlines, the alert panel) and AQHI colours. Rivers, fires and smoke carry `AtlasLayer.now` (`asOf`, `archiveEnd`, `build`); `main.ts` draws `now.build` at the Now stop, hatches the gap after `archiveEnd` and opens such a layer at Now. **`src/sky.ts`**: the sky right now for Light & dark's Sky now chip and the Town Report: the sun's position from the clock (`sunAt`, `sunAlt`, `sunLines`), the aurora grid (`auroraAt`, `auroraLive`, `AURORA_DROP_H`, `kpTonight`) and the picture drawn from both (`skyImage`).
- **`src/wind.ts`**: the Wind and Smoke forecast chips shared by Smoke & air and Wildfires (`airPanel`, `airLayers`, `airTooltip`; the chips' state, the plume's frames and picture, the scrubber). **`src/particles.ts`**: the particles (`createParticles`: CPU-advected, one `PathLayer` from typed arrays, spawned inside `Ctx.view`), `windAt`, `arrowPaths` and `reducedMotion`.
- **`src/history.ts`**: the daily record in the app: `dayT`/`tDay` (Saskatchewan day ↔ timeline time), `ensureFeed` (loads a feed's month files once, when the timeline enters a layer's recent span), and per-feed views (`riversHistory`, `firesHistory`, `airHistory`, `waterHistory`). A layer's `now.recent` (`RecentSpan` in `layer-kit.ts`) draws it; `main.ts` hatches only up to its first day and draws its sparkline dashed. `fireSeason(year)` loads one fire season (1 April to 31 October) for Wildfires' **Replay the season** (`AtlasLayer.replay`, built in `fires.ts`): while `state.replay` is set, `main.ts` gives the timeline to the season (`timeRange`), draws `replay.build` in place of the layer's own and a bar a day as the sparkline; `focus` on another layer ends it.
- **`src/metrics.ts`**: `townMetrics(data)` per place and the Town Finder `CRITERIA` / `rankTowns`, with the Finder weights saved in the browser (`loadWeights`, `saveWeights`). **`src/panels.ts`**: Town Report and Town Finder; the report places each layer's section, which lives in that layer's module (`schoolsRows` in schools.ts, `waterRows`, `homeCosts` in housing.ts, `rightNow` in now.ts…) and is built from **`src/report-kit.ts`** (`metric`, `na`, `link`, `tripV`/`tripSub`). A layer imports `TownMetrics` from metrics.ts as a type only, never a value. **`src/sources.ts`**: the Data & sources view (markup, cards, citation, growth); **`src/sources-catalog.ts`**: every source's entry (`ALL_SOURCES`: owner, licence, `read`, `rings`), the bark and what the atlas worked out itself (`DERIVED`); **`src/sources-round.ts`**: the tree-ring canvas (`createRound`). A new source adds its entry to the catalogue. **`src/events.ts`**: the event/feature panel.
- **`src/tours.ts`**: the guided tours (**Take the tour**, `?tour=<id>`): `TOURS` (step lists: `caption`, `camera`, `do`, `play`, `wait`) and the runner and caption bar (`initTours`). `main.ts` hands it the film handle's functions plus `reset`, `setSpeed`, `snapshot` / `restore` and the workplace; Exit restores what the tour found, *Explore from here* keeps the map. Captions are typed text set with `textContent`, and say only what the layer on screen shows; a tour sets no Finder weight or scenario and puts a borrowed workplace back. When a layer a tour visits changes, update its captions.
- **`src/data.ts`**: `loadAll()`, the JSON types, formatters. **`src/charts.ts`**: the d3 charts and ramps (`lineChart`, `bandChart`, `rampCSS`). **`src/html.ts`**: `esc()` / `safeUrl()`.
- **`scripts/fetch-data.mjs`**: the runner only: the stage `ORDER`, `npm run data now`, the manifests. Each stage is `scripts/stages/<name>.mjs`, whose default export does the work and is imported only when it runs. Shared helpers live in `scripts/lib/`: `config` (paths, `BBOX`, endpoints), `io` (`log`, `cached`, `fetchBuf`, `writeOut`, `writeNow`, `pool`), `apis` (OGC API, ArcGIS REST, Overpass with mirrors, StatCan WDS), `parse` (CSV, fractional years, `pdfText`/`advisoryRows`), `geo` (distances, `dp`, `vwRing`, `joinPaths`, `edgeKm`), `places` (`getProvince`, `inSask`, `getPlaces`, `getSmallPlaces`, `smallAreas`, `straightTimes`; the `places` stage primes them with `setPlaces`/`setSmallPlaces`), `drive` (OSRM, `driveTimes`), `census`, `needs-osm` (`NEEDS_KINDS`, `needsOSM`, the ODHF rows) and `shp` (`readShapefile`, `readDbf`, `lccFromPrj`: zipped polygon shapefiles in a Lambert conformal conic). A new stage gets its own file and a place in `ORDER`. **`scripts/history.mjs`** is the daily record's logic, kept free of the pipeline's modules; `scripts/stages/history.mjs` and `history-backfill.mjs` hand it its helpers.

## Data notes

- Crime: each place takes one police service's series (its own municipal one while current, otherwise the rural RCMP detachment of the same name); series are never spliced.
- Fires: CNFDB cause codes are `N` (natural/lightning), `H` (human), `H-PB` and `RE` (dropped), `U`. Burn outlines are NBAC's for burns of 200 ha or more (prescribed ones dropped), simplified by Visvalingam–Whyatt (`vwRing`: triangles of a sixth of the burn's width; Douglas–Peucker left spikes on its pixel-stepped edges), parts under 40 ha and islands under 200 ha dropped. A row is `[year, ha, polys, t, start-point indices]`; a start point inside a same-year outline (or within 1 km of its edge) draws no circle. NBAC's area is its own (less unburned islands), not the reported size.
- What grows here: each 3 km cell is its most common class of 36 samples (cloud and unmapped ignored), so small fields vanish (say so). Eleven classes grouped from the inventory's codes in the stage (`group`); code 130, too wet to be seeded, is in “other crops and fallow” and makes 2010–11 stand out. Shares are over the cells mapped every year; a place's land is its cells within 25 km, null when under half are mapped. Coverage stops around 55–56° N.
- Power grid: OSM only (SaskPower publishes no open grid map; its outage feed is undocumented and unlicensed, so it is not used). Lines are grouped by voltage class (230, 138, 72 kV, 0 untagged) and joined end to end; a substation mapped as a point and an outline is kept once. A place measures the nearest line (sampled every ~250 m) and substation from its town limits; never in the Finder.
- Internet: ISED tiers are what is offered (not measured); "Fixed 50/10" includes fixed wireless, excludes satellite; mobile is LTE or better (no 5G in the open data). Hexagons are drawn from ISED's centres as flat-topped hexagons (0.1206° wide spacing, rows 0.0168°/cos(lat) apart).
- Tiers: `municipalities.json` holds the 62 (`tier: 1`) and 417 small communities (`tier: 2`, `csd` uid, placed at their CSD outline's area centroid). `getPlaces()` returns tier 1 only; `getSmallPlaces()` tier 2; `smallAreas()` their town limits from `subdivisions.json`; `straightTimes()` their nearest targets as `{ f, min: null, km }`. `jobs` (region only), `needs`, `justice`, `hospitals`, `doctors`, `childcare`, `schools`, `internet`, `drought`, `radon` and `light` write a `small` table beside `towns`; a tier-1 table never changes. Not for tier 2: crime, population (the app uses the CSD's census counts), camping, transit, commute, tax, crops, industry, water, newcomer, projections, places of worship. In the app `data.munis` stays the 62 and `data.small` holds tier 2; `smallView` (src/small.ts) merges the `small` tables and CSD census values so `townMetrics` and the Finder handle both; `rankTowns` skips tier 2 on `drive` criteria. `atlas:town` and `openPlace` route a key to the Town Report or `renderSmallReport`.
- Census subdivisions (`src/subdivisions.ts`): `csdTint` draws a census layer's measure for all 951 subdivisions under its columns; `csdReport` is the census-only report (an AtlasEvent via `describe`), and `csdClick` sends a click on a place's own subdivision to its Town Report or small-community report. Suppressed values are untinted and read "—" (`missing`); `ne` (an incompletely enumerated reserve, the data quality flag's first digit) reads "not enumerated"; a rural municipality excludes the towns inside it (say so). The Finder reads the 62 unless "Include small communities" is ticked.
- Who lives here: census counts are randomly rounded to 5, so a share on a rounded 0 shows "—" (`pctText` and `share` in `src/subdivisions.ts`); the Finder's Diverse community is the immigrant share only. Reserves are separate CSDs, not in a town's Indigenous identity share.
- Newcomer services: settlement offices are read as text from IRCC's locator script (`services-info.js`, never run); Service Canada and SGI issuers are OSM only, and insurance brokers stand in for SGI issuers (inferred; say so).
- Doctors & clinics: clinics are ODHF SHA sites plus OSM (merged when close with the same first name word); ODHF sites with no point, or a point more than 15 km from the town they name, sit at their town centre (`approx`; Hospital access does the same, and the ministry's post-secondary points in Schools); a place with no clinic mapped but a hospital in town gets `h` and counts that hospital as its clinic (inferred, like the in-town police rule). SHA service disruptions are web notices only, so none are mapped; a clinic is not a doctor taking new patients (say so).
- Childcare: the Ministry of Education's regulated list is read from the saskatchewan.ca finder page (its `<li>` list and the parallel `window.pageList` points, as text). Crown copyright, non-commercial only. Family homes keep no name or address: a count per community at a point rounded to 0.02°. No capacity in the source; listings with no type are classed by name (inferred). A point outside its community's limits (small communities included) sits at that community's centre (`approx`).
- Schools: the ministry list gives grades only for band schools; provincial schools' elementary/high comes from the name, and an unstated one counts as K-12 (`gi`) when no stated high school is within 10 km. The ministry layer misplaces ~⅓ of schools, so each snaps to a same-named OSM school within 30 km; schools it lacks inside the 62 places' limits are added from OSM (sector `osm`, never French). Drives skip Hutterite colony, band and independent schools.
- Radon: Health Canada's 2009–2011 survey by 2007 health region (the three northern RHAs pooled as `4714`) and FSA; each place takes the region its centre is in and its city FSAs (≥¼ of its town-limit outline points, or holding its centre), else its rural FSA. FSAs with under 20 tests are "few tests". The Finder's Lower radon uses the region share (weight 0).
- Light & dark: computed, not measured (say so). Day length for the build year (NOAA equations, 90.833° / 96°); aurora bands are NOAA SWPC's Kp rule (oval edge ≈ 66° − 2°·Kp) on the IGRF-14 centred-dipole geomagnetic latitude, never a probability; geomagnetic latitude is shown rounded down (`mlText`) so it never reads across a band edge. Dark-sky preserves come from the RASC table matched to park names (Sask. parts only); OMB Nocturnal Preserve has no open outline.
- Getting around: scheduled service is OurAirports' flag (not a timetable); OSRM routes over OSM winter roads, so far-north airports count as drive targets (the stage warns if one is ever nearest). Intercity bus and VIA come from OSM only (bus coverage partial: say so). Moose Jaw's GTFS has expired and Prince Albert's is the Mobility Database's copy; neither states a licence. The Finder's Can live without a car counts what is mapped in town, not frequency.
- Property tax: a Home costs chip, not its own layer (`tax.json`). Indicative only (say so): 2021 census median value × 80 % (residential percentage of value) × (uniform mill rate × residential factor + residential education rate, the median of the places' school levy ÷ assessment) ÷ 1000; base tax, minimum tax, library and special levies are flagged but never added. Lloydminster (own charter) gets a rate but no estimate. The workbook's layout changes between years (2025 spells out the status, `City` for `C`, and says Education for School): the stage accepts both and throws when under 80 % of the places match, so a new layout keeps the old `tax.json`.
- Smaller rules: drinking-water notices not yet in effect go to `water.json` `scheduled` (never `sites`), and revoked ISC advisories are dropped; a census owner or renter 30 %+ rate of 0 that the household counts contradict is left out (suppressed, never 0); Hail counts a research-database storm within 2 days and 25 km of a radar swath once; Drought draws each month's map at the end of its month; a river gauge whose normal peak is 0 has no ratio and is not counted as reporting.
- The daily record (`scripts/history.mjs`, `npm run data history`, run on demand only, after `now`): lives on the **`data-history` branch**, never main; `live.yml` checks it out into `public/data/history/` (gitignored), rolls up, and its `archive` job (the only one with `contents: write`, runs no repository code) copies the result over the branch, additive only. **Never splice**: a recent span starts the first day after the archive's last year, so provisional days never join the official series and drop out of view once the archive publishes their year. A missed run is a gap, never a zero. Rivers and AQHI days are recomputed whole from the feeds' own windows; hotspots are de-duplicated by position and minute (CWFIS ids are not stable) and never feed the wildfire statistics; alerts continue a row when seen again within 6 h (keyed by code, type, places and region names). Fires, alerts and water are counted only when their stage refreshed its file in this run or succeeded within 3 h (manifest); otherwise that step fails and nothing is stamped. A river or AQHI day is never replaced by one with fewer readings. The build fails when it cannot tell whether `data-history` exists (only `ls-remote` exit 2 means absent), and the archive job starts the branch only when the build found none. `history-backfill` reaches back once (gauges ~30 days, AQHI ~3 days, CWFIS `public:hotspots` the whole season via WFS 2.0 with `srsName=CRS:84`).
- Right now: every live value shows its age (`ageTag`; `plainAge` for hotspots, whose list window is 24 h, so staleness comes from the list's read time). A river flag (`ice`, `est`) gets an amber ring; a silent gauge is "no reading", never zero. Hotspots are not confirmed fires (say so). AQHI is borrowed from the nearest community within 150 km, outside Saskatchewan included (`out`); never chart it with smoke days. Alerts are grouped by code and text, `esc()`'d, and a place is covered when its centre is in a region. Live values never feed the Finder. The aurora (`now/aurora.json`, Light & dark's Sky now chip; hidden with `?film`) is a model's forecast of aurora overhead, not a sighting (say so): it shows the time it is for and the age of the solar wind reading behind it, and is not drawn once that time is 3 h past, stricter than the 24 h rule because the oval moves in minutes. Night's shade and the sunrise and sunset lines are computed in the browser and drawn even without the file. Its outlook line (`kpTonight`) is NOAA's Kp forecast for the coming dark hours read against the light stage's Kp rule: a count of places, never a probability. `auroraCell` (now.ts) gives the Town Report and the small-community report their cell; `skyLink` opens the layer on the chip. It is not rolled into the daily record.
- The season replay (Wildfires): hotspots only, counted as hotspots, never fires or a burned area; a missed day is a grey gap, never a zero; a season still running plays to its last day on record. Its dashed edges are the atlas's own estimate (`spreadEdges`: hotspots on a ~2 km grid, each cell's first day, edges around patches of `SPREAD_MIN` cells), not CWFIS's perimeters, which the daily record does not keep (say so). NBAC outlines fade in at the end only for a year the composite has published. The button is hidden with `?film` (no record is loaded), but `atlas.replaySeason(year)` reads the record anyway.
- Wind and Smoke forecast (`src/wind.ts`, chips on Smoke & air and Wildfires; hidden with `?film`): model forecasts, never readings (say so, with the run and the hour shown). They draw only at Now, from the layers' `now.build` (`airLayers`; when both layers are on, only the first draws). The wind is dropped once its hour is 3 h past (`WIND_DROP_H`), a smoke frame once the next frame's time has passed. The trails count nothing; forecast smoke is PM2.5 from fires only and is never charted with the AQHI or smoke days. Not in the Town Report, the Finder or the daily record.
- Climate twins (the Climate layer’s **Climate twin** chip, `twins.json`): a place’s observed normals (its nearest station with temperature and precipitation, within 120 km; borrowed, say so at both ends) plus the projected change since the normals’ period, matched to the Saskatchewan station whose normals today are nearest on annual mean temperature and precipitation, each scaled by its spread across the stations; farther than 0.6 is no twin, and above every station reads “warmer than anywhere in Saskatchewan today” (a finding, shown plainly). The projections are changes from 1971–2000, so the share already made by the normals’ period is the atlas’s own straight-line estimate (say so). The 10th and 90th percentile twins are looked for among stations no warmer / no cooler than the median’s, so a range never reads backwards. A station takes a place’s name only when it is that place’s own station within 30 km. A model range matched on two numbers, never a forecast: badged, per scenario with its range, never in the Finder.
- Scenarios and projections: a scenario is the visitor's own (banner, red, never in the Town Report or Finder); a projection is a model range (hatched, badged, a band, never a single value or a Finder criterion). Outlooks show issue and valid times and drop once valid time passes.
- 3D cities (`src/buildings.ts`, the `buildings` stage): MapLibre layers, not deck.gl, so they sit on terrain. The PMTiles reader is imported with the first tile and the source lists tile URLs (not a TileJSON), so nothing is fetched below zoom 12. Footprints are Microsoft's machine-drawn ones (StatCan's Open Database of Buildings sits behind a browser check that refuses scripts); a footprint with no OSM height stands one nominal storey (say so). The flag `f` is 1 floodway, 2 the rest of the 1:500-year extent, 3 only behind dikes: "touches the mapped extent", never "will flood", and never in the Finder. Past zoom 12 the tiles' extents (full detail) are the water and River floods' simplified ones go transparent (still picked); gauge columns are hidden from zoom 11 (the camera would sit inside one). Terrain is raised only from zoom 12 (`TERRAIN_Z`): deck.gl's layers are drawn flat and slide off it at province scale.
- Voting (`src/voting.ts`, the `voting` stage): federal only (Elections Saskatchewan states no licence). A poll is a polling division; its stations (A, B…) are summed, and a division whose results were merged ("Merge With") is drawn as part of its host. Polls 500+ are mobile polls (drawn on their building, or a point when it collapses at the 1e-4° grid), 600+ advance polls (one per advance polling district, no area: their dots are spread over the district's polls by electors on the list, the atlas's own placement), `S/R` special ballots (riding totals only, never drawn). Turnout is ballots cast (rejected included) ÷ electors on the lists, per advance district (election day + advance); a poll's own election-day figure reads low and is only in its panel. Rejected ballots count only in turnout. Polls are redrawn before every election and ridings changed in 2023: never compare polls across elections. 2011 is riding level only; the history before it is `hfer_e.csv`'s general elections from 1908, grouped by Parliament (deferred ridings joined, by-elections dropped); the pre-1942 Conservatives are their own key (`con`). A place counts the polls whose inside point is in its limits, else the poll holding its centre (`c`, say so); its advance votes join only when every advance district of those polls is 90 %+ (by electors) inside it (`adv`), otherwise turnout is election day only (say so). Dots: one per 5 votes, a seeded random share kept farther out (1 per 10 below zoom 9, 1 per 20 below 7). Standard party colours, plain counts, no commentary, never in the Finder.
- Overpass is often at capacity; the client retries across mirrors and caches only complete JSON.

## Verifying in the browser

Load `/?film` (it skips the live readings; `/?film&now` loads them), wait for the map, then e.g. `atlas.clearMap(); atlas.focus('crime'); atlas.setTime(2024.5)` or `atlas.openTown('north battleford')`. When the browser pane is hidden the map's frame loop is throttled; take a screenshot before trusting a visual check. The handle also has `tour('province' | 'town' | 'hazards' | 'people')` (runs a guided tour; `tours` lists them), `openSmall`, `openFinder`, `setPlaying`, `setPanelOpen`, `setMenu`, `showSources`, `setClosed` / `clearScenario`, `replaySeason(year)` / `leaveReplay()` (Wildfires' season replay; resolves true once it is playing) and `map`, `state`, `data`, `layers`. In the dev container, set `ATLAS_WATCH_POLL` if edits made on the Windows side are not picked up (`vite.config.ts`).
